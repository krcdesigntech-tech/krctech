# Plan: krctech UI/UX 재설계

## Context

기존 사이드바에 `AI 질문`(스트리밍 채팅)과 `AI 봇`(비동기 Q&A)이 분리 노출되어
사용자가 두 기능의 차이를 인지하기 어렵다. 또한 `문서 관리`는 사이드바에서
admin 전용으로 숨겨져 있어, 비관리자 사용자가 어떤 문서가 검색/AI 질문 대상인지
확인하기 어렵다.

대시보드도 정적 통계 중심이라 핵심 워크플로우인 `질문 → 답변 확인 → 문서 확인`으로
이어지는 진입점이 약하다.

**목표**: 메뉴 구조 정리 + 대시보드 개선 + AI 어시스턴트 통합 + 문서 페이지 역할 분리

---

## 핵심 결정사항

1. **AI 진입점은 `/ai`로 통합**
   - `/ai?tab=chat`: 채팅 세션 목록
   - `/ai?tab=bot`: 비동기 봇 Q&A
   - `/chat/[sessionId]`: 기존 스트리밍 채팅 상세 URL 유지
   - `/chat`: `/ai?tab=chat`으로 redirect
   - `/ask`: `/ai?tab=bot`으로 redirect

2. **컴포넌트는 복제하지 않고 분리 재사용**
   - 기존 `/chat/page.tsx`, `/ask/page.tsx` UI를 `/ai/page.tsx`에 인라인 복제하지 않는다.
   - `ChatSessionsPanel`, `BotQuestionsPanel`, `QuickQuestion` 같은 클라이언트 컴포넌트로 분리한다.

3. **문서 권한은 UI와 API를 함께 맞춘다**
   - admin: 기존 관리 기능 유지. 업로드, 삭제, 처리 상태, 오류 재처리 가능.
   - non-admin: 읽기 전용. `ready` 문서만 표시. 업로드/삭제/재처리 불가.
   - 버튼 숨김만으로 끝내지 않고 API와 직접 URL 접근도 차단한다.

4. **문서 범위는 이번 작업에서 기존 user scope를 유지**
   - 현재 RLS/RAG 구조는 기본적으로 `user_id` 기준이다.
   - 이번 UI 개선에서는 non-admin에게 `본인 소유의 ready 문서`를 읽기 전용으로 보여준다.
   - 조직 공용 문서가 필요하면 `documents.visibility` 또는 `organization_id` 도입, RLS/RPC/RAG 변경이 필요한 별도 작업으로 분리한다.

### 2. 신규: `/ai` 통합 AI 어시스턴트 페이지

**파일**: `src/app/(dashboard)/ai/page.tsx` *(신규)*

두 개의 탭을 URL searchParam으로 구분한다.

| 탭 | URL | 기능 |
|----|-----|------|
| 채팅 | `/ai?tab=chat` | 기존 채팅 세션 목록 |
| 봇 Q&A | `/ai?tab=bot` | 기존 비동기 질문 폼 + 답변 목록 |

기본 탭:
- `tab` 값이 없거나 알 수 없는 값이면 `chat`으로 처리한다.

구현 방식:
- `'use client'`
- `useSearchParams()`로 현재 탭 읽기
- `useRouter()`로 탭 전환 시 URL 업데이트
- 탭 버튼은 실제 링크처럼 동작하도록 `router.replace('/ai?tab=...')` 사용
- 탭 콘텐츠는 분리된 컴포넌트를 렌더링

```tsx
<Header title="AI 어시스턴트" />

<Tabs>
  <Tab active={tab === 'chat'}>채팅</Tab>
  <Tab active={tab === 'bot'}>봇 Q&A</Tab>
</Tabs>

{tab === 'chat' ? <ChatSessionsPanel /> : <BotQuestionsPanel />}
```

탭 스타일:
- `border-b-2` active/inactive 구분
- active: `border-primary text-primary`
- inactive: `border-transparent text-gray-500 hover:text-gray-700`

### 5. 대시보드 재설계

**파일**: `src/app/(dashboard)/dashboard/page.tsx` *(수정)*

새 레이아웃:

```text
┌─────────────────────────────────────────────────────────┐
│ 웰컴 섹션: "안녕하세요 N님" + 역할 배지 + 날짜          │
├─────────────────────────────────────────────────────────┤
│ 빠른 질문 입력 카드 (QuickQuestion)                      │
│  textarea 2줄 + "봇에게 질문하기" 버튼                   │
│  → POST /api/bot/ask → /ai?tab=bot                       │
├────────────────────────┬────────────────────────────────┤
│ 최근 봇 질문 (3개)     │ 최근 AI 채팅 (3개)             │
│  - 질문 텍스트          │  - 세션 제목                   │
│  - 상태 배지            │  - 메시지 수 + 날짜            │
│  - 완료 시 답변 미리보기│  - "계속하기" → /chat/[id]    │
│  "더 보기" → /ai?tab=bot│ "더 보기" → /ai?tab=chat      │
└────────────────────────┴────────────────────────────────┘
│ KPI 4카드: 문서수·완료·처리중·대화수                    │
└─────────────────────────────────────────────────────────┘
```

Supabase 쿼리:
- 최근 문서 목록: 필요 시 최대 3~5개
- 최근 채팅 세션: `chat_sessions`, 사용자별, `updated_at DESC`, 3개
- 최근 봇 질문: `bot_questions`, 사용자별, `created_at DESC`, 3개
- KPI count는 목록 길이로 계산하지 않고 count 쿼리 사용

KPI 개선:
- 현재 구현은 `limit(5)`로 가져온 문서/세션 배열 길이를 KPI로 사용하므로 실제 전체 수와 다를 수 있다.
- 아래처럼 별도 count 쿼리를 병렬로 추가한다.

```typescript
supabase.from('documents').select('*', { count: 'exact', head: true }).eq('user_id', user.id)
supabase.from('documents').select('*', { count: 'exact', head: true }).eq('user_id', user.id).eq('status', 'ready')
supabase.from('documents').select('*', { count: 'exact', head: true }).eq('user_id', user.id).in('status', ['uploading', 'processing'])
supabase.from('chat_sessions').select('*', { count: 'exact', head: true }).eq('user_id', user.id)
```

링크 정책:
- 최근 채팅 항목: `/chat/[sessionId]`
- 최근 채팅 더 보기: `/ai?tab=chat`
- 최근 봇 질문 더 보기: `/ai?tab=bot`
- 기존 `/chat` 링크는 `/ai?tab=chat`으로 변경

#### 6-1. 서버 래퍼

**파일**: `src/app/(dashboard)/documents/page.tsx` *(수정)*

역할:
- `createClient()`로 user/profile 조회
- `isAdmin` 계산
- `DocumentsClient`에 `isAdmin` 전달

```tsx
export default async function DocumentsPage() {
  const supabase = await createClient()
  const {
    data: { user },
  } = await supabase.auth.getUser()

  const { data: profile } = await supabase
    .from('profiles')
    .select('role')
    .eq('id', user!.id)
    .single()

  const isAdmin = profile?.role === 'admin'

  return <DocumentsClient isAdmin={isAdmin} />
}
```

#### 7-1. 공통 role helper

**파일**: `src/lib/auth/role.ts` *(신규 검토)*

기존 `src/lib/law/auth.ts`의 `requireAdmin`과 중복되지 않도록 공통 helper로 분리한다.

```typescript
export async function getCurrentUserWithRole() {
  const supabase = await createClient()
  const {
    data: { user },
  } = await supabase.auth.getUser()

  if (!user) return { user: null, role: null, isAdmin: false }

  const { data: profile } = await supabase
    .from('profiles')
    .select('role')
    .eq('id', user.id)
    .single()

  return {
    user,
    role: profile?.role ?? null,
    isAdmin: profile?.role === 'admin',
  }
}
```

## 검증 방법

### 자동 검증

```bash
node_modules/.bin/tsc --noEmit
npm run lint
npm run build
```

### 라우팅

1. `/ai` 접속 시 채팅 탭 표시
2. `/ai?tab=chat` 접속 시 채팅 탭 표시
3. `/ai?tab=bot` 접속 시 봇 Q&A 탭 표시
4. `/ai?tab=unknown` 접속 시 채팅 탭으로 처리
5. `/chat` 접속 시 `/ai?tab=chat` redirect
6. `/ask` 접속 시 `/ai?tab=bot` redirect
7. `/chat/[sessionId]` 접속 시 기존 채팅 상세 정상 동작

### Sidebar

1. 모든 메뉴 링크 정상 작동
2. `/ai`, `/ai?tab=bot`, `/chat/[sessionId]`, `/ask`에서 `AI 어시스턴트` active 표시
3. admin/non-admin 모두 `문서` 메뉴 표시
4. admin 메뉴는 admin에게만 표시

### Dashboard

1. 빠른 질문 제출 후 `/ai?tab=bot` 이동
2. `bot_questions`에 pending 행 생성
3. 최근 봇 질문 3개 표시
4. 최근 AI 채팅 3개 표시
5. KPI count가 실제 전체 개수 기준으로 표시

### Documents

Admin:
1. 전체 관리 UI 표시
2. Upload 버튼 표시
3. Delete 버튼 표시
4. 처리중/오류 상태 문서 표시
5. `/documents/upload` 직접 접근 가능
6. 업로드/삭제/재처리 API 호출 가능

Non-admin:
1. 읽기 전용 문서 UI 표시
2. Upload/Delete/재처리 버튼 없음
3. `ready` 문서만 표시
4. `/documents/upload` 직접 접근 차단
5. 업로드/삭제/재처리 API 직접 호출 시 403
6. 문서 상세는 본인 소유 ready 문서만 접근 가능
7. "AI에게 질문하기" 클릭 시 해당 문서 ID가 포함된 채팅 세션 생성

### Regression

1. 기존 채팅 스트리밍 응답 정상
2. 채팅 상세의 문서 필터 정상
3. 봇 Q&A pending/processing 폴링 정상
4. 문서 검색 결과 정상
5. 관계법령 메뉴/페이지 영향 없음
